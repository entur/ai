# Guide template for the Entur Developer Portal

This is the canonical template for writing how-to guides. Every guide published
on the Developer Portal should follow this structure. Text inside `[brackets]`
is instructions -- replace with actual content.

---

## Template

```markdown
# How to [complete the sentence, keep it short and on point]

This guide shows you how to [complete the sentence, describing what you can
accomplish by using this guide].

Eager to start experimenting with code? Head over to our
[API documentation]([link to the relevant API reference]).

## Before you begin

To use this guide, you need to:

- Be an Entur partner
- Get your [authentication]([link to authentication guide])
- (Optional) [Write optional prerequisites like this]

## 1 [Header describing the step]

[Description of the step. Note that headers never end with a period.]

### Example: [Header describing the topic of the example]

[Write one to two sentences describing what you can see or explore in the
example.]

[Include a code block with the example]

## (Optional) 2 [Header describing the step]

[This is how to write optional steps in the guide. Note that optional steps
also have a number in the header.]

## 3 [Header describing the step]

[Description of the step.]

## Next steps

You made it! Here is what you can do next:

- [Bullets, written as entire sentences, containing links.]
- [Do not include more than five bullets.]

## Related topics

[Note that it is optional to include related topics.]

- [Bullets, written as entire sentences, containing links.]
- [Do not include more than five bullets.]

*Last updated on [date]*
```

---

## Writing conventions

### Language

- British English spelling (organisation, colour, authorisation, behaviour)
- Oxford style guide for capitalisation and punctuation
- Active voice, present tense
- Plain, direct language
- One sentence per thought

### Heading capitalisation (Oxford standard)

Only the first word and proper nouns are capitalised:

- Correct: "New approaches in mobility research"
- Incorrect: "New Approaches in Mobility Research"

### Concepts and hover text

Concepts should not be described in detail in the guide. Such descriptions belong
under Concepts in the Developer Portal. When you reference key concepts in the
text, link to the relevant concept page so the reader can access more information.

### Formatting markers used in the original template

- `[H1]` = Markdown `#` (one per guide, the title)
- `[H2]` = Markdown `##` (sections and numbered steps)
- `[H3]` = Markdown `###` (examples within steps)
